# 项目流程、实现理由与面试讲解

这是一份围绕已运行代码的说明。业务背景沿用两次实习：第一次用 SQL 落实科研指标，第二次把查询接入后端。下面表名、类名、版本和参数是 2026 年重建实现。

## 1. 数据如何进入系统

45 GB 原始 CSV → 识别年份区段 → 有读取上限的抽样 → 统一 13 列样本 → 500 行 JDBC 批量 upsert → MySQL 原始观测表。

没有按文件前几万行直接截断，因为那样大概率只得到 1973 年的一些站点，无法计算“1973–1992 基准对比 1993 年以后”的完整链路。抽样器先用 512 个稀疏探测定位年份区段变化，再二分定位变化处。每个所需年份读取 2 MiB 前缀，排除窗口末尾可能截断的站点，最后选跨所需年份都存在的 3 个站点。数据年份区段顺序实际上为 1973–1989、2020–2023、2010–2019、1990–2009。

发现的原始文件问题与处理：

- 不同区段湿度列位于地理字段之前或之后。按年份区段投票确定列序，缺湿度的行也沿用该区段布局，避免空值造成二次错列。
- 站点号若丢前导零，补到 11 位；`FRSHTT` 补到 6 位，补在左边。例如 `10000` → `010000`，代表雨。
- NOAA 缺失温度 `9999.9`、缺失降水 `99.99` 转为 NULL；湿度按 0–1 比例校验。来源说明：[NOAA GSOD 字段定义](https://www.ncei.noaa.gov/data/global-summary-of-the-day/doc/readme.txt)。
- 原始文件已经包含 LTD 等历史派生列，本次忽略并按明确规则重算。

数据库联合主键 `(station_code, observation_date)` 防止同一站点同日重复。再次导入同样的样本采用 upsert 更新原值，原始行数保持不变。导入器只接受规范化且 <=64 MiB、<=200,000 行的样本文件，不接收 HTTP 传入的任意文件路径。

## 2. 第一阶段：为什么分四步计算

第一步，用 1973-01-01 到 1993-01-01（不含）的温度、降水、湿度，为每站点分别算五个阈值。重建采用明确的经验分位定义：将某变量非空观测排序，取第 `ceil(p*n)` 项。每个变量至少有 30 条有效基准观测才发布该站阈值。测试小样本环境把最低数设为 2。

旧 SQL 的 `PERCENT_RANK` 再取范围边界与这个定义不完全相同；重建文档公开这一差异。科研项目最终应由需求方确认分位数口径。这里选经验 nearest-rank，是为了让 SQL、手算和独立校验一致。

第二步，把分析期原始观测按站点连接阈值表，生成逐日指标：

| 指标 | 公式 | 单位 |
|---|---|---|
| LTD | max(0, TEMP10 − TEMP) | °F 差值 |
| HTD | max(0, TEMP − TEMP90) | °F 差值 |
| HR | max(0, PRCP − PRCP95) | 英寸 |
| EHR | max(0, PRCP − PRCP99) | 英寸 |
| LH | max(0, HUMIDITY5 − HUMIDITY) | 湿度比例差 |
| HTD1 | max(0, MAX − 95) | °F 差值 |
| CTD1 | max(0, 5 − MIN) | °F 差值 |

7 个都是幅度，不把 HTD1/CTD1 改成 0/1 标志；年度统计再判断幅度是否 >0。另拆出六类天气标记。NOAA 的标记 0 同时包含“未报告”，不能把它解释成确定没有事件。缺失观测保持 NULL，不伪装成没有极端事件的 0。没有基准阈值的后续观测不进入指标表，数量明确记录在元数据里。

第三步，按 **日期 + 地区层级 + 地区字段 + 指标** 汇总 7 项幅度。均值、最小和最大用聚合函数；中位数用窗口行号与组内个数，奇数取中间一项、偶数取中间两项平均。旧草稿漏日期分组，本版包含日期，测试还验证了两个日期不会混算。

第四步，按站点和年份统计 13 类指标的非零天数，同时返回有效天数。再把各站的年度天数按地区求均值、最小、最大和中位数。它不是事件发生概率；观测不完整时也不做全年外推。年度元数据如果同站同年跨不同地区，重算会报错，要求先解决地理口径。

## 3. 第二阶段：一次查询怎么走

以四川达县阈值为例：浏览器在请求头携带 X-API-Key，调用 `/api/stations/57328099999/thresholds` → Spring Security 认证并校验 READER 角色 → Controller 校验 11 位站点号 → Service 组织查询 → Redis 查缓存 → 未命中时 MyBatis 参数化查询阈值表 → 回填 Redis → 返回 JSON。

实际样本计算得到该站 `TEMP10=43.9°F`、`TEMP90=82.4°F`、`PRCP95=0.83 英寸`、`PRCP99=2.09 英寸`、`HUMIDITY5=0.5056259581`。温度基准有效样本 7302，降水 7160，湿度 7301。面试可现场请求接口核对。

逐日查询直接通过 `(station_code, observation_date)` 联合主键定位；MyBatis 使用 `#{}` 绑定值。地区和指标是 Java 枚举/固定表列，地区名称是绑定参数，没有用 `${}` 拼接用户 SQL。频繁查询的阈值和地区统计进入缓存；逐日明细只分页查库。

## 4. Redis、事务与索引为什么这样做

缓存使用 String JSON 和 cache-aside。key 包含计算版本、查询种类、规范化筛选参数的 SHA-256。TTL 30 分钟；同一请求返回 `X-Cache` 方便演示。Redis 故障回源数据库，因为结果表才是权威来源。缓存 key 带版本，重算提交后切换版本，旧 key 自然过期；缓存不参与 MySQL 本地事务。

样本导入和四阶段计算由 `DatasetLoader.load` 的外层事务覆盖；失败时连同新导入观测一起回滚。只重算时也在一个事务内执行 DML：锁住单行 `analysis_state` 以串行化管理写操作，删除并重建结果、更新版本，提交后再切换缓存版本。普通查询使用 InnoDB 已提交的结果，执行期间仍能看到前一个完整版本。这种做法适合当前小数据工具；大规模历史全量重算应改为离线构建新版本后短事务发布。

导出在 REPEATABLE READ 只读事务中，先核对行数上限，再每次查询 500 行写出 CSV。最多 20,000 行，控制内存与事务长度。它使用 offset 分页，当前规模够用；更大导出可改为日期游标，长导出则应离线执行。

联合主键适合“站点等值 + 日期范围”查询，地区索引对应地区过滤。`scripts/explain.sql` 对同一查询比较正常计划和显式忽略索引后的计划；小样本单次耗时只说明执行路径，不当作原实习的优化百分比。

## 5. 如何讲个人经历

“第一次实习按指标说明写 SQL，第二次参与把已有查询接入后端。准备秋招时，我找回了原始气象 CSV，用受限抽样重建了一个完整版本：从字段清洗和指标计算，到查询、导出、缓存与测试。原先的接口路径和参数没有留存，现在展示的是这次复建的代码。”

可以用本次实际故障说明排查过程：独立端到端验证发现地区日查询返回 503；日志显示 SQL 别名 `maxValue` 与 MySQL 保留字 `MAXVALUE` 冲突；给别名加标识符引号，补日聚合 HTTP 回归测试，再运行样本 oracle。该问题发生在此次复建，不是当年的线上事故。

本次增强已使用 Spring Security 保护全部业务接口，API Key 映射 READER/ADMIN 两种服务角色：只读身份只能查询/导出，管理员能重算和运行增量任务；无认证 401、角色不足 403。密钥由本机随机生成，不存在公开默认口令。它仍没有个人账号、用户级数据权限或 JWT 体系；默认只监听本机，生产化需要 HTTPS、凭据管理与更完整的权限模型。这些是本次新增能力，不属于当年已确定的实习工作。

## 6. 本次新增：Spring Scheduling 增量处理

上游将标准化小 CSV 写成 .part，关闭后原子改名为 .csv；定时器按 fixedDelay 调用同一 runOnce 服务。独立收件目录、有界快照、稳定期、文件大小/行数/每轮数量限制，避免扫描原始 45 GB 数据。内容 SHA-256 在 MySQL 唯一去重，改名不重复，改内容可订正。

文件处理在独立 Spring Bean 的事务方法内：锁 analysis_state → 检查指纹 → upsert 原始观测 → 重算受影响站点的基准/全部历史指标/年统计 → 重建地区统计 → 更新版本和成功标记 → 提交后切换缓存。基准期订正会改变历史阈值，所以不能只计算新增日期；地区中位数不能简单做差量更新，当前保留重聚合。

CSV 或计算异常时连已经 flush 的批次也回滚，失败审计通过 REQUIRES_NEW 单独保存；自动最多三次固定退避重试，管理员可以显式再试。成功后原文件保留，数据库成功标记防止重启后重复计算。不是分布式 exactly-once，也不保证数据库宕机时失败审计仍能写入。

面试可以现场演示 README 的权限矩阵、任务状态、专用测试库中的失败回滚和真实定时触发；不要把新增功能改写成历史实习已做过的复杂生产架构。
